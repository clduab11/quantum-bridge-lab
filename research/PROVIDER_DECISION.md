## Smallest useful next step

Residual differences remain explicit. Claude prefers a historical stress-rate planning default and a human-led amendment decision; Codex requires current rate verification and follows the actual delegated authority. v2's remaining stop-or-amend wording is not adopted as an exhaustive choice while the Chat route remains unmeasured. Nor is its proposed maximum-fixture count plus an arbitrary margin sufficient by itself to prove a worst-case input ceiling. A defensible endpoint-specific bound or equivalent verified accounting contract is still required. The review cannot grant or remove authority; this phase exercises neither freeze nor paid execution. There is no forced consensus on these points.

Prepare one complete candidate request profile for Sol Chat Completions using only direct, current documentation: role mapping for the unchanged prompts; explicit supported decoding; `n: 1`; inclusive `max_completion_tokens: 8192`; no tools, model fallback, LLM seed or conversation linkage; documented explicit no-cache behavior; expected response/error/usage schema; disabled SDK retries and the existing outer deadlines. Record the nullable/deprecated fingerprint honestly.

Resolve the endpoint-specific input-token ceiling and actual price/billing contract before proposing any paid action. The Responses counting endpoint's guarantee cannot simply be transferred to Chat requests. If adequate evidence cannot be obtained within this bounded effort, retain the software and stop before paid exposure; alternatively, consider a separately reviewed prospective amendment with its limitation explicit. There is no commitment to an experiment merely because the harness now exists.

Only after the request profile, protected storage/custody, token/billing bounds and a full two-stage monetary proposal are concrete should an E9 authority decision be sought. Format-only smoke tests cannot prove optimization performance, stationarity or universal schema compliance. Both study stages, the fixed analysis and all failure rules remain intact.
