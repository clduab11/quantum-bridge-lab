# Counted runner integration plan

Implement a prospective CountedArmRunner subclass using the existing ArmRunner initialization, slots, correction parser, deadlines, cancellation and no-replay lifecycle. Preserve the v0.4 implementation unchanged. A typed injected provider prepares immutable count/generation bytes and returns classified attempt results. The provider contract owns wire validation, credential and price authority, durable pre-send evidence, billing settlement and observable-identity checks; this runner owns per-class attempt reservations, retries, receipt lifetime, admission, global halt propagation and forfeit causes. No live provider is wired by this component.

Files: src/qbridge/counted_runner.py and tests/test_counted_runner.py. Tests use synthetic objectives, temporary private journals and a fabricated provider. Confirm three count retries are distinct from three generation retries, count failure never opens correction, admission rejection never sends generation, the only correction follows received zero-valid text and obtains a new receipt, server minimum waits are never shortened, the deadline bounds both classes, global halt survives a new runner, and interruption cannot replay an arm. Test a real sequential ProcessExecutor path with durable provider evidence, not only a mutable in-memory callback.

The selected candidate admission limit is 272000; constructor values are explicit to support smaller synthetic boundary tests and must be bound by the eventual frozen execution configuration. This module does not select a provider, adopt a protocol amendment, verify billing or satisfy a freeze gate. An actual adapter and execution entry point must refuse calls without authority; no such live entry point is introduced here.
